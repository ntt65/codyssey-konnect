# Vercel + Render 배포 방법

작성일: 2026-10-30 · 기준 브랜치: `main`

## 배포 구조

| 서비스 | 역할 |
|---|---|
| GitHub | 소스 관리. Vercel과 Render가 같은 저장소의 main을 사용 |
| Vercel | frontend/의 HTML·CSS·JavaScript 제공 |
| Render | FastAPI 실행, 문서 검색 및 LLM 호출 |
| Supabase | pgvector 기반 RAG 자료 저장 |
| LLM 제공자 | OpenAI 또는 OpenAI 호환 Naito API로 답변 생성 |

사용자가 Vercel 화면에서 질문하면 Render의 `/api/ask`를 호출한다.
Render는 Supabase에서 관련 문서를 검색한 뒤 LLM에 근거를 전달하고 답변과 출처를 반환한다.
검색용 임베딩은 현재 OpenAI를 사용하므로 답변 제공자가 Naito여도 OpenAI 키가 필요하다.

현재 저장소에 render.yaml이나 vercel.json은 없다. 아래는 각 서비스 대시보드에서 직접 설정하는 방법이다.
배포만으로 문서가 자동 적재되지는 않는다.

## 1. Render 백엔드 만들기

1. Render에 로그인한다.
2. **New → Web Service**를 선택한다.
3. 팀이 배포하기로 합의한 GitHub 저장소를 연결한다. `lab678` 연결은 저장소 통합이 승인·완료된 뒤 진행한다.
4. 다음 값을 입력한다.

| 항목 | 값 |
|---|---|
| Branch | `main` |
| Language / Runtime | Python 3 |
| Root Directory | 비워두기 — 저장소 루트 사용 |
| Build Command | `pip install -r backend/requirements.txt` |
| Start Command | `uvicorn app.main:app --app-dir backend --host 0.0.0.0 --port $PORT --no-access-log` |
| Health Check Path | `/health` |

현재 main.py가 frontend 폴더도 정적 파일로 참조하므로 Root Directory를 backend로 제한하지 않는다.
`$PORT`는 Render에서 제공하는 포트를 사용한다. 운영에서는 `--reload`를 넣지 않는다.
`--no-access-log`는 원본 URL·쿼리 대신 앱의 요청 ID 기반 안전한 접근 로그를 사용하기 위한 설정이다. 플랫폼 자체 로그와 별도 추가 로그에도 비밀값을 넣지 않는다.
로컬 고정 버전은 `.python-version`의 3.12.13이다. Render의 Python 버전도 맞추고 빌드 로그를 확인한다. pip 빌드에 사용하는 `backend/requirements.txt`는 `uv.lock`에서 생성한 런타임 의존성 파일이다.

### 환경변수

Render의 **Environment**에 아래 설정을 추가한다. 비밀값은 저장소에 작성하지 않는다.

```env
APP_ENV=production
LLM_PROVIDER=openai
OPENAI_API_KEY=실제_OpenAI_API_키
OPENAI_MODEL=실제_사용할_모델
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
SUPABASE_DB_URL=실제_Postgres_연결_문자열
RAG_COLLECTION=knowledge
RAG_TOP_K=5
RAG_SIMILARITY_THRESHOLD=0.35
RAG_EMBEDDING_DIMENSION=1536
CORS_ALLOW_ORIGINS=https://실제사이트.vercel.app
```

위 값은 예시이므로 실제 값으로 교체한다.
Vercel 배포 전이면 배포 후 확정된 주소로 CORS 값을 수정하고 Render에 반영한다.
주소는 경로와 마지막 슬래시 없이 origin만 입력한다. 여러 주소는 쉼표로 구분한다.

Naito로 답변을 생성하려면 아래 설정을 추가·변경한다.

```env
LLM_PROVIDER=naito
NAITO_BASE_URL=실제_OpenAI_호환_API_기본_주소
NAITO_API_KEY=실제_키
NAITO_MODEL=실제_모델명
```

현재 질문 API는 Supabase Auth를 사용하지 않는다. 따라서 RAG 데모에 SUPABASE_URL·SUPABASE_PUBLISHABLE_KEY·SUPABASE_SECRET_KEY는 필수가 아니다.
health의 `configuration`은 현재 사용하는 기본 화면 또는 RAG의 필수 설정만 검사한다. 설정 준비와 실제 외부 연결 성공은 구분한다.

### 배포 확인

배포가 완료되면 Render 주소를 기록한다. 예: `https://실제백엔드.onrender.com`.

- `/health`: 서버 응답 확인. HTTP 200만으로 DB·LLM 연결 성공까지 증명되지는 않는다.
- `/docs`: API 명세 및 `/api/ask` 확인.

## 2. Vercel 프론트엔드 만들기

1. Vercel에서 **Add New → Project**를 선택한다.
2. 같은 GitHub 저장소를 Import한다.
3. 다음 설정으로 배포한다.

| 항목 | 값 |
|---|---|
| Production Branch | `main` |
| Root Directory | `frontend` |
| Framework Preset | `Other` |
| Build Command | Override를 켜고 비워두어 빌드 생략 |
| Output Directory | `.` — frontend 폴더 자체 |

현재 프론트엔드는 순수 HTML·CSS·JavaScript이므로 별도 빌드가 필요 없다.
설정 화면이 다르면 Project Settings의 Build and Deployment 및 Git 설정에서 값을 확인한다.
배포 후 실제 Vercel 주소를 Render의 CORS_ALLOW_ORIGINS에 등록한다.

## 3. 화면과 Render API 연결

**현재 코드에는 실제 Render 주소가 설정되어 있지 않다. 배포 전에 아래 연결 설정을 추가해야 한다.**
frontend/js/rag.js는 `window.RAG_API_BASE`가 없으면 같은 origin의 `/api/ask`를 호출한다.
Vercel과 Render를 나누어 쓰려면 frontend/index.html의 rag.js 로드 직전에 공개 API 주소를 설정한다.

```html
<script>
  window.RAG_API_BASE = "https://실제백엔드.onrender.com";
</script>
<script type="module" src="./js/rag.js"></script>
```

실제 Render 주소로 교체하고, API 주소 끝에는 슬래시를 붙이지 않는다.
이 주소는 공개 서버 주소이며 API 키를 넣는 곳이 아니다.
순수 정적 HTML이므로 Vercel 환경변수에 주소를 입력하는 것만으로 이 코드에 자동 주입되지는 않는다.
설정 변경을 커밋·push하고 Vercel에서 새 배포가 반영되었는지 확인한다.

## 4. RAG 자료 적재

배포만으로 자료가 적재되지는 않습니다. 로컬 적재 환경과 Render의 DB·컬렉션·임베딩 모델·차원을 맞춘 뒤 [RAG 안내](./rag_guide.md#나중에-자료-추가)의 적재 명령을 실행합니다. 형식·재적재·삭제 제약도 그 문서에서 관리합니다.

## 5. 최종 확인

1. Vercel 홈페이지가 열리는지 확인한다.
2. 질문 전송이 Render의 `/api/ask`로 향하는지 브라우저 Network에서 확인한다.
3. 등록 자료에 답이 있는 질문을 보내 답변과 출처를 확인한다.
4. 등록 자료와 무관한 질문은 근거 부족 안내를 하는지 확인한다.
5. 서버 연결 실패가 정상 빈 결과와 구분되는지 확인한다.

| 증상 | 확인할 내용 |
|---|---|
| Vercel의 /api/ask가 404 | RAG_API_BASE 및 최신 프론트 배포 확인 |
| CORS 오류 | Render에 실제 Vercel origin 등록 여부 확인 |
| 자료 저장소 미설정 안내 | Render의 SUPABASE_DB_URL 확인 |
| 관련 근거 없음 | 실제 자료 적재 여부·컬렉션·질문 내용·유사도 기준 확인 |
| 검색 오류 | DB 연결, OpenAI 임베딩 키, 모델과 차원 일치 여부 확인 |
| 답변 생성 오류 | LLM_PROVIDER와 해당 제공자의 키·모델·주소 확인 |
| frontend 폴더 관련 시작 실패 | Render Root Directory가 저장소 루트인지 확인 |

현재 질문 API는 공개 데모용이다. 실제 서비스 공개 범위에 맞춰 인증과 사용량 제한을 별도로 결정한다.
이 문서는 배포 절차이며, 실제 Vercel·Render 배포 및 연결 완료를 의미하지 않는다.
