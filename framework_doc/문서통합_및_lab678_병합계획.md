# 문서 통합 및 lab678 저장소 병합 계획

갱신: 2026-10-30. 사용자가 직접 검토할 수 있도록 두 계획을 한 파일에 모았다. **문서 통합을 먼저 진행하며 lab678 병합은 나중에 팀 합의 후 진행한다.**

## 1. 문서 통합

| 이전 문서 | 처리 |
|---|---|
| `framework.md` | 구조·설계·개발 절차·오류 계약·검증 기준의 기준 문서로 재작성 |
| `framework_design.md` | 현재 설계를 흡수하고 원본 상세는 [참고_초기설계.md](./참고_초기설계.md)로 보존 |
| `framework_workflow.md` | 현재 절차를 흡수하고 원본 상세는 [참고_초기개발절차.md](./참고_초기개발절차.md)로 보존 |
| `README.md` | 설치·로컬 실행·테스트와 상세 문서 연결로 축약 |
| `배포방법.md` | 별도 운영 안내로 유지하고 적재 상세는 RAG 안내로 연결 |
| `rag_guide.md` | 자료 적재·RAG 사용에 집중하고 설치·서버 명령은 README로 연결 |
| 체크리스트·CLAUDE·기술 문서·인덱스·트리 | 새 기준 문서와 연결하고 삭제 문서 참조 정리 |

순서: 코드 대조 → 기준 문서 재작성 → 설계·절차 흡수 → 중복 제거 → 참조 갱신 → 이전 두 문서의 역할 명시·이름 변경 → 링크·명령 확인 → 별도 커밋.

없는 study 경로·과거 브랜치 구상·DB 미설정 503·검증되지 않은 Identity Linking을 현재 기능처럼 복사하지 않는다. 설치는 README, 적재는 RAG 안내, 배포 설정은 배포방법에서 관리한다. 문서 전체를 매번 읽지 않고 필요한 절만 읽는다. 필요한 상세 자료는 참고 문서로 보존하고, 과거 내용과 현재 지침을 구분한다. 무리한 문서 삭제는 하지 않는다.

현재 구조·계약은 [framework.md](./framework.md), 상태·완료 증거는 [준비체크리스트](./준비체크리스트.md)를 기준으로 확인한다. 이 파일은 통합 결정과 순서의 기록이다.

## 2. lab678 병합 — 보류

대상: [Lab678-Hackathon/lab678](https://github.com/Lab678-Hackathon/lab678). 대상 구조·기본 브랜치·보호 규칙은 아직 확인하지 않았다. 원격 변경·통합 브랜치·push·PR·병합을 지금 실행하지 않는다.

| 단계 | 수행할 일 |
|---|---|
| 팀 합의 | 범위·제외 자료·배치·시점·담당자 결정 |
| 기준 확인 | 구조·기존 작업·기본 브랜치·PR 규칙·양쪽 기준 커밋 확인 |
| 별도 준비 | 현재 작업 보존, 별도 작업 디렉터리와 통합 브랜치 사용 |
| 방식 선택 | 공통 이력·중복 확인 후 이력 병합 또는 파일 이관 합의. 이력 강제 결합은 자동 선택하지 않음 |
| 충돌 정리 | README·에이전트 지침·환경·의존성·CI·배포 설정 통합 |
| 제외 확인 | `.env`·키·`.venv`·캐시·개인 절대 경로 제외 |
| 로컬 검증 | 대상 경로에서 깨끗한 설치·전체 테스트·홈페이지·헬스·대표 API 확인 |
| 실제 연결 | RAG·배포 검증과 미검증 범위 기록 |
| PR 검토 | 사용자 지시 후 push·PR, 팀 리뷰·CI 확인 |
| 병합 | 팀 합의와 사용자 병합 지시 후 실행, 팀원 clone·실행·배포 커밋 확인 |

완료 기준: 기존 팀 작업을 보존하면서 합의된 기본 브랜치에서 팀원이 같은 안내로 설정·실행·검증한다. 실행 체크박스·담당자·확인 기록은 [준비체크리스트](./준비체크리스트.md) §4에서 관리한다.
