## 2. lab678 병합 — 보류

### 2026-10-30 브랜치 복사 실행 결과

사용자 후속 지시로 **현재 두 브랜치만 그대로 복사 완료**했다. 아래 계획의 복사 미실행 설명은 계획 작성 당시 기록이다. 최신 main 기준 이관 대신 원본 framework 기준을 사용했으며 develop 통합은 나중에 진행한다.

| 대상 브랜치 | 원본·대상 일치 SHA |
|---|---|
| [framework](https://github.com/Lab678-Hackathon/lab678/tree/framework) | `b50ecd52cbd62f3aa4100e87d6cfc467483558e2` |
| [konnect](https://github.com/Lab678-Hackathon/lab678/tree/konnect) | `3de4d55fbf014d87bdc5ad1e2c504b4b7939d466` |

실행 전 원본 원격·로컬 SHA 일치와 대상 이름 부재를 확인했다. 두 브랜치 도달 이력에서 .env·개인키 파일 경로 및 주요 비밀값 패턴을 검사했으며 탐지 항목은 없었다. 이는 모든 민감정보가 없다는 보장은 아니다. 명시한 두 SHA만 atomic push로 새 브랜치에 복사한 뒤 원격 ref를 재조회했다.

대상 develop은 전후 `c021a308ae3679cd342c9af9e2a2f11ac06b96c2`, main은 `569745bb39b4521c1ff405c679677d18198d1b3c`로 동일하다. 기본 브랜치 변경·develop 반영·PR·병합·배포는 실행하지 않았다. 원본 브랜치와 기존 미커밋 변경도 보존했다. 코드 변경 없이 ref를 복사했으므로 앱 테스트는 재실행하지 않았다. 대상 clone·실행 검증과 선택적 통합은 후속 작업이다.

### 2026-10-30 브랜치 복사 계획 구체화

이번 요청은 계획 작성이다. 아래 조사 결과가 이전의 미확인 설명보다 우선한다. 브랜치 이동·원격 변경·push·PR·병합은 실행하지 않았다.

| 대상 | 실제 확인 결과 |
|---|---|
| lab678 | Public, 기본 브랜치 `develop`. 조회 결과 `main`, `develop`, `TEAM_WORKFLOW`, `docs/align-team-workflow` 존재 |
| 대상 루트 | backend·frontend·docs·design·.github 및 README·TEAM_WORKFLOW·AGENTS·CLAUDE·GEMINI·환경 예시 존재 |
| 로컬 main | `be0221633e61125ca46e79683ce389973441448e`: 최신 범용 프레임워크 |
| 로컬 framework | `b50ecd52cbd62f3aa4100e87d6cfc467483558e2`: main보다 12개 커밋 뒤, 독자 커밋 0개 |
| 로컬 konnect | `3de4d55fbf014d87bdc5ad1e2c504b4b7939d466`: 기존 관광 앱. 범용 프레임워크와 화면·API·기능이 다름 |

근거: [대상 구조](https://github.com/Lab678-Hackathon/lab678/tree/develop), [README](https://github.com/Lab678-Hackathon/lab678/blob/develop/README.md), [TEAM_WORKFLOW](https://github.com/Lab678-Hackathon/lab678/blob/develop/TEAM_WORKFLOW.md), [AGENTS](https://github.com/Lab678-Hackathon/lab678/blob/develop/AGENTS.md), 로컬 ref·커밋 수 비교. 대상 내부 코드 전체·보호 설정·공통 이력·소스 원격 최신 상태는 미확인이다.

**권장안: 두 참고 브랜치 보관과 실제 서비스 통합을 분리한다.**

1. 최신 범용 프레임워크가 목적이면 `main`의 검증된 기준을 대상 `framework`로 복사한다. 현재 framework 그대로 복사하면 최근 오류 처리·공통 지침·uv 잠금·CI 등 12개 개선 커밋이 빠진다. 예전 상태 보관이 목적이면 `b50ecd5`를 선택한다. 원본 framework 이동은 별도 지시가 있을 때 진행한다.
2. 팀 확인과 이력 공개 검토 후 대상에 `framework`·`konnect`를 독립 참고 브랜치로 복사한다. 기본 브랜치는 develop로 유지한다. 참고 브랜치 생성은 서비스 채택·배포를 뜻하지 않는다.
3. 실제 사용할 코드는 최신 `lab678/develop`에서 `feature/import-framework`를 만들어 필요한 파일만 선택적으로 이관한다. konnect 기능은 후속 작업에서 필요한 부분만 가져온다.
4. 대상 환경에서 검증한 후 `feature/import-framework → develop` PR을 만든다. `develop → main`은 팀장 최종 승인과 별도 사용자 지시를 따른다.

팀 문서는 기존 KONNECT의 선택적 재사용을 정하고 있다. 참고용 전체 브랜치 보관도 팀 의도와 맞는지 실행 전 확인한다. 원본 이력 보관이 불필요하거나 공개에 부적절하면 참고 브랜치 복사를 생략하고 develop 기반 파일 이관만 진행한다.

| 순서 | 실행할 작업 | 완료 증거 |
|---|---|---|
| 1 | 기존 변경 보존, 별도 작업 디렉터리 준비 | 시작 status·보존 위치 |
| 2 | 양쪽 최신 ref·기준 SHA·보호 규칙·이름 중복·공통 이력 확인 | SHA 및 비교 결과 |
| 3 | 프레임워크 기준·참고 보관 여부·통합 범위·담당자 팀 확인 | 공통 영역 변경 전 관련 팀원 확인 기록 |
| 4 | 복사할 전체 도달 이력의 키·개인정보·비공개 자료·대용량 파일 검토 | 현재 파일뿐 아니라 과거 이력 검토 결과 |
| 5 | 지시 후 선택한 두 SHA를 새 참고 ref로 복사 | 대상 ref SHA와 선택한 소스 SHA 일치 |
| 6 | 최신 develop 기반 작업 브랜치에 필요한 파일 이관 | 기존 팀 작업을 보존하는 diff와 소스 SHA |
| 7 | 충돌 정리·설치·테스트·화면 검증 | 실제 실행 결과 및 미검증 범위 |
| 8 | 지시 후 push·develop PR·팀 공유 | 변경·검증·제약을 기록한 PR |
| 9 | 팀 규칙과 별도 지시에 따라 병합·배포 | 팀원 새 clone 재현·CI·실제 배포 커밋 |

브랜치 복사는 명시적 refspec으로 두 ref만 전송한다. `--mirror`, `--all`, `--force`는 사용하지 않는다. 이름이 중복되면 덮어쓰지 않고 SHA를 비교해 새 이름을 합의한다. `.gitignore`는 과거 이력을 보호하지 않으므로 이력 검토 전 push하지 않는다. 문제가 있으면 원본 이력을 임의 재작성하지 않고 안전한 현재 파일의 스냅샷 이관을 선택한다.

독립 이력의 참고 브랜치에서 develop로 바로 PR을 만들거나 `--allow-unrelated-histories`로 강제 결합하지 않는다. develop 기반 파일 이관 브랜치로 일반 PR을 만든다.

통합 시 대상 `TEAM_WORKFLOW.md`, 팀 README, PR·Issue 템플릿과 docs·design을 보존한다. 에이전트 지침은 대상 TEAM_WORKFLOW 참조를 유지한다. 소스의 자동 로컬 커밋 규칙을 덮어쓰지 않는다. 대상은 명시적 요청 시 커밋·push하는 규칙이다. 환경 예시는 변수 이름만 통합하며 실제 .env·키·.venv·캐시·개인 설정은 제외한다.

백엔드·프론트·테스트·문서는 범용 RAG와 공통 계약 중심으로 이관하고 Auth·Topic 호출부 영향을 확인한다. Python 버전·pyproject·uv.lock·requirements는 묶어서 검토한다. .github 팀 템플릿을 보존하고 CI의 develop PR·push 실행 조건을 확인한다. Secrets·자동 배포 연결은 별도 구성한다. 관광 자료·영상·과거 검증 자료는 일괄 이관하지 않는다.

프레임워크 이관 후 대상 루트에서 README에 따라 잠금 설치하고 다음을 확인한다.

```text
uv sync --locked
uv run --locked python utils/scripts/sync_requirements.py --check
uv run --locked python utils/scripts/setup_dev.py --feature basic
uv run --locked python utils/scripts/verify_dev.py
uv run --locked python -m pytest -q
node --test tests/frontend/http.test.mjs
```

키·실서비스 없이 모의 검증한 뒤 브라우저·실제 DB/LLM·인증·배포를 별도 확인한다. 소스의 과거 71+7개 통과를 대상 검증 완료로 쓰지 않는다. konnect는 해당 브랜치의 실행·의존성·검증 절차를 따로 확인한다. 병합 전에는 작업 브랜치 수정·PR 닫기로 대응하고, 병합 후에는 되돌리기 PR과 마지막 정상 배포 커밋 복귀를 검토한다.

아래는 이전 보류 계획이다. 상세 실행 기준은 위 구체화 계획을 따른다.

완료 기준: 기존 팀 작업을 보존하면서 합의된 기본 브랜치에서 팀원이 같은 안내로 설정·실행·검증한다. 실행 체크박스·담당자·확인 기록은 [준비체크리스트](./준비체크리스트.md) §4에서 관리한다.
