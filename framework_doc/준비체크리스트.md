# 해커톤 전 준비 체크리스트

작성일: 2026-10-30

목표: 주제 발표 후 자료와 역할 프롬프트를 교체해 바로 시작할 수 있도록, 배포된 화면에서 RAG가 실제로 동작하는지 확인한다.

## 현재 확인된 상태

- [x] 관광 데이터 없는 범용 RAG 구현
- [x] 문서 적재, 근거 검색, 답변·출처 API 구현
- [x] 홈페이지 질문 화면 구현
- [x] Core·RAG 테스트 29개 통과
- [x] 실행·자료 적재·배포 방법 문서 작성
- [ ] 실제 DB·임베딩·LLM 연결 검증
- [ ] 실제 브라우저에서 질문 전송과 출처 표시 확인
- [ ] Vercel·Render 배포 및 연결 확인
- [ ] 팀원 PC에서 실행 확인

위의 미완료 항목은 이 세션에서 아직 검증하지 못한 항목이다. 이미 별도로 완료했다면 결과를 확인하고 체크한다.

## 1. 실제 RAG 연결 확인 — 먼저 진행

- [ ] 사용할 LLM 제공자와 모델 확정
- [ ] 루트 .env에 임베딩용 OPENAI_API_KEY와 SUPABASE_DB_URL 설정
- [ ] 답변 제공자에 맞게 OpenAI 또는 Naito 설정 입력
- [ ] 검증용 짧은 .md 또는 .txt 문서 하나 준비 — 관광 자료 불필요
- [ ] 자료 적재 명령 실행 및 성공 확인
- [ ] 로컬 서버 실행 후 홈페이지 열기
- [ ] 문서에 답이 있는 질문을 보내 답변과 출처 확인
- [ ] 문서에 답이 없는 질문에 근거 부족 안내가 나오는지 확인
- [ ] 오류 안내와 정상 빈 결과가 구분되는지 확인
- [ ] 임시 검증 자료를 실제 앱 자료와 분리 — 검증용 컬렉션 사용 가능

완료 기준: 실제 DB와 LLM으로 적재 → 검색 → 답변 → 출처 확인을 한 번 끝낸다.
설정·명령: [RAG 사용 안내](./rag_guide.md).

## 2. Vercel·Render 배포

- [ ] Render에 저장소의 main을 연결하고 Web Service 생성
- [ ] Python 버전, 빌드·시작 명령, 환경변수 설정
- [ ] Render의 /health 및 /docs 접근 확인
- [ ] Vercel에 같은 저장소의 frontend 폴더 배포
- [ ] frontend/index.html에 실제 Render 주소를 RAG_API_BASE로 설정
- [ ] Render의 CORS_ALLOW_ORIGINS에 실제 Vercel origin 등록
- [ ] Render와 자료 적재 환경의 컬렉션·임베딩 모델·차원 일치 확인
- [ ] 배포된 홈페이지에서 답변·출처와 근거 부족 안내 확인
- [ ] 모바일 또는 좁은 화면에서 입력·전송·출처 펼치기 확인

완료 기준: 팀원이 Vercel 주소를 열어 실제 자료 기반 답변을 확인한다.
상세 설정: [배포 방법](./배포방법.md).

## 3. 팀원에게 전달

- [ ] 팀원 PC에서 저장소를 받아 가상환경·의존성 설치
- [ ] 비밀값은 커밋하지 않고 별도로 전달
- [ ] 실행 안내만 보고 서버를 실행할 수 있는지 확인
- [ ] 담당자 지정: 화면 / API·LLM / 자료 적재 / 배포
- [ ] Vercel·Render 주소와 운영 설정 담당자를 팀에 공유

## 4. 소스 반영 확인

- [ ] git status로 미커밋 변경 확인
- [ ] 필요한 코드·문서 변경 커밋
- [ ] GitHub main에 최신 작업 반영 여부 확인
- [ ] framework도 같은 기준으로 유지할 경우 최신 커밋 동기화 및 push 확인
- [ ] 배포 서비스가 실제로 최신 main 커밋을 사용 중인지 확인

이 문서 작성 직전 로컬 main은 origin/main과 동기화된 상태였다.
이후 추가된 체크리스트 등은 별도로 커밋·push해야 한다.
